=head1 NAME

Uji::Node::ListBox - a visible, scrollable (single- or multi-) selection list

=head1 SYNOPSIS

    use Uji;

    Uji::list_box(
        value     => $model->{count},
        options   => [ map { { value => $_, label => "Row $_" } } 1 .. 10 ],
        on_select => sub ($v) { { type => 'SET_COUNT', value => $v } }
    );

    # Multi-select: value is an arrayref of selected values.
    Uji::list_box(
        multiple  => 1,
        value     => [ 2, 5 ],
        options   => [ map { { value => $_, label => "Row $_" } } 1 .. 10 ],
        on_select => sub ($v) { { type => 'SET_PICKS', value => $v } }    # $v is an arrayref
    );

=head1 DESCRIPTION

L<Uji::Node::ListBox> is a visible scrollable list. A single selection is stored as a scalar in the model; with
L</multiple> the value is an B<arrayref> of selected option values. On Win32 it is a native C<LISTBOX>; multi-select
lists use the B<LBS_MULTIPLESEL> style so ordinary clicks toggle each row.

=head1 Constructor

=head2 C<new ( %params )>

You normally use the L<Uji|Uji/list_box> helper.

=head3 Parameters

=head4 C<value>

The currently selected option's C<value>. With L</multiple> it is an arrayref of selected option values. Default C<''>.
Recomposed live by the reconciler.

=head4 C<options>

Array reference of C<< { value => ..., label => ... } >> hashrefs. The C<label> defaults to the C<value>. When the
options change, the reconciler rebuilds the list's item strings.

=head4 C<on_select>

A callback receiving the selected option's C<value> (or an arrayref of them when L</multiple>):

    on_select => sub ($v) { { type => 'SET_COUNT', value => $v } }

Return a message hashref (or C<undef> to ignore the event).

=head4 C<multiple>

Boolean, default false. When true the list allows several rows to be selected at once and the value (and C<on_select>
argument) is an arrayref of the selected option values.

=head3 Inherited Parameters

L<Uji::Node::ListBox> inherits the common parameters from L<Uji::Node|Uji::Node/Parameters>: C<flex>, C<enabled>,
C<visible>, C<tooltip>, C<x>/C<y>/C<w>/C<h>, and C<id>.

=head1 Methods

=head2 C<value>

Returns the selected option's C<value> (or the arrayref of selected values when L</multiple>).

=head2 C<options>

Returns the array reference of C<< { value => ..., label => ... } >> options.

=head2 C<on_select>

Returns the selection callback (or C<undef>).

=head2 C<multiple>

Returns true when the list allows multiple selections.

=head2 C<type>

Returns the string C<'list_box'>.

=head1 How it Works

On Win32 the list is a native C<LISTBOX> created with C<WS_VSCROLL>, C<WS_BORDER>, C<LBS_NOTIFY> (C<0x1>, so a change
posts C<WM_COMMAND>), and C<LBS_NOINTEGRALHEIGHT> (C<0x100>, so the list honors the exact laid-out height). L<multiple>
adds C<LBS_MULTIPLESEL> (C<0x8>): ordinary clicks toggle each row's state. Items are added as UTF-16 via
C<LB_ADDSTRING>; selecting fires C<LBN_SELCHANGE> (C<1>) whose index is translated back to the option's C<value>
through C<LB_GETCURSEL> (or, for multi-select lists, the set of indices read via C<LB_GETSELCOUNT> / C<LB_GETSELITEMS>
is reported as an arrayref of values).

The I<len> used by L<Uji::Layout|Uji::Layout/DESCRIPTION> is the value stored in the model, never a handle-mutating
call.
