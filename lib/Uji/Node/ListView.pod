=head1 NAME

Uji::Node::ListView - a multi-column, scrollable selection list (a table)

=head1 SYNOPSIS

    use Uji;

    Uji::list_view(
        value   => $model->{sku},
        columns => [
            { label => 'SKU',   width => 120 },
            { label => 'Name',  width => 200 },
            { label => 'Price', width => 80 },
        ],
        rows => [
            ['AB-12', 'Apples',  '3'],
            ['AB-21', 'Bananas', '2'],
            { value => 'CD-34', columns => ['CD-34', 'Cherries', '5'] },   # value defaults to the first cell
        ],
        on_select => sub ($v) { { type => 'SET_SKU', value => $v } }
    );

    # Multi-select: value is an arrayref of selected row values.
    Uji::list_view(
        multiple => 1,
        value    => ['AB-12', 'CD-34'],
        columns  => [ { label => 'SKU', width => 120 } ],
        rows     => [
            { value => 'AB-12', columns => ['AB-12'] },
            { value => 'AB-21', columns => ['AB-21'] },
            { value => 'CD-34', columns => ['CD-34'] },
        ],
        on_select => sub ($v) { { type => 'SET_PICKS', value => $v } }    # $v is an arrayref
    );

    # Sortable columns, drag-to-reorder, and a formatted money column.
    Uji::list_view(
        sortable    => 1,
        reorderable => 1,
        columns => [
            { label => 'SKU',   width => 120 },
            { label => 'Price', width => 80, format => '$%0.2f', sort => 'numeric' },
        ],
        rows  => [
            ['AB-12', '3'],
            ['AB-21', '2'],
        ],
        on_sort    => sub ($col, $dir) { { type => 'RESORT', column => $col, dir => $dir } },    # re-sort your own rows here
        on_reorder => sub ($order) { { type => 'REORDER_COLS', order => $order } },              # $order = new left-to-right column indexes
    );

=head1 DESCRIPTION

L<Uji::Node::ListView> is a visible, scrollable multi-column list (a table). A single selection is stored as a scalar
in the model; with L</multiple> the value is an B<arrayref> of selected row values. On Win32 it is a native
C<SysListView32> in report (details) view.

=head1 Constructor

=head2 C<new ( %params )>

You normally use the L<Uji|Uji/list_view> helper.

=head3 Parameters

=head4 C<value>

The currently selected row's C<value>. With L</multiple> it is an arrayref of selected row values. Default C<''>.
Recomposed live by the reconciler.

=head4 C<columns>

Array reference of C<< { label => ..., width => ... } >> hashrefs defining the column headers. C<width> (pixels)
defaults to the measured label width, C<label> defaults to C<''>. Optional per-column keys: C<sort> (C<'text'> or
C<'numeric'>, default C<'text'>) picks the comparator used when the column is clicked (C<sortable> lists click the
headers to sort); C<format> applies a C<sprintf> format to numeric cells for display (e.g. C<{ label => 'Price',
width => 80, format => '$%0.2f' }> renders C<12.5> as C<$12.50> — cells always C<sort> by their raw value); and
C<align> (C<'left'>, C<'center'> or C<'right'>, default C<'left'>) maps to the native C<LVCFMT_LEFT/CENTER/RIGHT>
header alignment. When either the C<columns> or the C<rows> property changes the table is rebuilt; a rows-only
change (e.g re-applying the app's own sorted C<rows>) reuses the live native columns so user-resized widths and a
drag-reordered column order survive. The sorted column's header carries a sort indicator glyph (C<▲> ascending /
C<▼> descending) that follows the column wherever a header drag has moved it.

=head4 C<rows>

Array reference of the rows. Each row is either an arrayref of cell strings or a C<< { value => ..., columns => [...] } >>
hashref; in the arrayref form the row's C<value> defaults to the first cell. When the rows change the reconciler
rebuilds the table's contents.

=head4 C<on_select>

A callback receiving the selected row's C<value> (or an arrayref of them when L</multiple>):

    on_select => sub ($v) { { type => 'SET_SKU', value => $v } }

Return a message hashref (or C<undef> to ignore the event).

=head4 C<on_sort>

A callback received after the user clicks a column header (only when L</sortable>): C<on_sort =E<gt> sub ($col,
$dir) { ... }> where C<$col> is the column index and C<$dir> is C<'asc'> or C<'desc'>. A click on a new column sorts
it ascending; clicking the same column again toggles the direction. The driver reorders the L</rows> optically, but
the model C<rows> are untouched - an app typically re-sorts its own C<rows> here to match. Return a message hashref
(or C<undef>).

=head4 C<on_reorder>

A callback received after the user drags a column header off its place (only when L</reorderable>):
C<on_reorder =E<gt> sub ($order) { ... }> where C<$order> is an arrayref of the new left-to-right column indexes.
The native control already rearranges the visible table; the app usually rewrites its C<columns>/C<rows> model order
to match. Return a message hashref (or C<undef>).

=head4 C<sortable>

Boolean, default false. When true the column headers are clickable and a click reorders the visible rows by that
column (see C<columns>/C<sort> for the comparator; C<formatted> columns still sort by their raw values). The native
control raises C<LVN_COLUMNCLICK>, which the driver turns into a sort + L</on_sort>.

=head4 C<reorderable>

Boolean, default false. When true the user can drag column headers sideways to reorder the columns (the
C<LVS_EX_HEADERDRAGDROP> extended style). The new order is detected by the driver and reported through L</on_reorder>.

=head4 C<multiple>

Boolean, default false. When true the table allows several rows to be selected at once and the value (and C<on_select>
argument) is an arrayref of the selected row values. The Win32 control drops the C<LVS_SINGLESEL> style so ordinary
clicks toggle each row.

=head4 C<full_row_select>

Boolean, default false. When true the entire row highlights on selection (the C<LVS_EX_FULLROWSELECT> extended style).

=head4 C<grid_lines>

Boolean, default false. When true the table draws cell separator lines (the C<LVS_EX_GRIDLINES> extended style).

=head4 C<header>

Boolean, default true. When false the column header bar is hidden (the C<LVS_NOCOLUMNHEADER> style).

=head3 Inherited Parameters

L<Uji::Node::ListView> inherits the common parameters from L<Uji::Node|Uji::Node/Parameters>: C<flex>, C<enabled>,
C<visible>, C<tooltip>, C<x>/C<y>/C<w>/C<h>, and C<id>.

=head1 Methods

=head2 C<value>

Returns the selected row's C<value> (or the arrayref of selected values when L</multiple>).

=head2 C<columns>

Returns the array reference of C<< { label => ..., width => ... } >> columns (possibly carrying C<sort>/C<format>).

=head2 C<sortable>

Returns true when clicking a column header sorts the table.

=head2 C<reorderable>

Returns true when the user can drag column headers to reorder the columns.

=head2 C<rows>

Returns the array reference of rows.

=head2 C<on_select>

Returns the selection callback (or C<undef>).

=head2 C<multiple>

Returns true when the table allows multiple selections.

=head2 C<full_row_select>

Returns true when the whole row highlights on selection.

=head2 C<grid_lines>

Returns true when cell separator lines are drawn.

=head2 C<header>

Returns 1 when the column header bar is shown, 0 when it is hidden.

=head2 C<type>

Returns the string C<'list_view'>.

=head1 How it Works

On Win32 the table is a native C<SysListView32> created with the report view style C<LVS_REPORT> (C<0x1>) and
C<LVS_SHOWSELALWAYS> (C<0x8>); L</multiple> omits C<LVS_SINGLESEL> (C<0x4>) and L</header> adds C<LVS_NOCOLUMNHEADER>
(C<0x4000>). After creation the driver sets the extended styles C<LVS_EX_DOUBLEBUFFER> (C<0x10000>), C<LVS_EX_GRIDLINES>
(C<0x1>) per L</grid_lines>, C<LVS_EX_FULLROWSELECT> (C<0x20>) per L</full_row_select>, and C<LVS_EX_HEADERDRAGDROP>
(C<0x10>) per L</reorderable>, via C<LVM_SETEXTENDEDLISTVIEWSTYLE>.

Columns are added with C<LVM_INSERTCOLUMNW> and an 72-byte C<LVCOLUMNW> packed to the Win64 layout (mask/fmt/cx at
0/4/8, pszText at 16). The first column of each row is inserted with C<LVM_INSERTITEMW>; later cells are written into
the existing item with C<LVM_SETITEMW> (C<LVM_SETITEMTEXTW> is avoided: it silently no-ops for subitems). All text is
UTF-16, copied by the control during the call so the buffers are freed immediately.

The model's selection is applied with C<LVM_SETITEMSTATE> carrying an C<LVITEMW> (mask C<LVIF_STATE>, state and
stateMask C<LVIS_SELECTED>); all rows are cleared first, then each matching row is selected and scrolled into view with
C<LVM_ENSUREVISIBLE>. User clicks raise C<LVN_ITEMCHANGED>, whose row index is routed back to the model value through a
driver-side slot table (and, for L</multiple> tables, the whole native selection is read back via C<LVM_GETITEMCOUNT> /
C<LVM_GETITEMSTATE>). Programmatic selection is suppressed so the native echo never dispatches a spurious C<on_select>.

When L</sortable>, a header click makes the native control raise C<LVN_COLUMNCLICK> (the driver reads the column index
from the notification). The driver re-permutes a slot table of raw cells (so a C<formatted> number column still sorts
numerically), rebuilds the native rows with C<LVM_DELETEALLITEMS> + insert/set, re-selects the previously selected
values (suppressed), and calls L</on_sort>. When L</reorderable> the native header drag reorders columns and data by
itself; each driver poll queries the order array with C<LVM_GETCOLUMNORDERARRAY> (C<0x103B>) and dispatches
L</on_reorder> when it moves.

The I<len> used by L<Uji::Layout|Uji::Layout/DESCRIPTION> is the value stored in the model, never a handle-mutating
call.
