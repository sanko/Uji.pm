=head1 NAME

Uji::Node::ListView - a multi-column, scrollable selection list (a table)

=head1 SYNOPSIS

    use Uji;

    Uji::list_view(
        value   => $model->{sku},
        columns => [
            { label => 'SKU',   width => 120 },
            { label => 'Name',  width => 200 },
            { label => 'Price', width => 80 },
        ],
        rows => [
            ['AB-12', 'Apples',  '3'],
            ['AB-21', 'Bananas', '2'],
            { value => 'CD-34', columns => ['CD-34', 'Cherries', '5'] },   # value defaults to the first cell
        ],
        on_select => sub ($v) { { type => 'SET_SKU', value => $v } }
    );

    # Multi-select: value is an arrayref of selected row values.
    Uji::list_view(
        multiple => 1,
        value    => ['AB-12', 'CD-34'],
        columns  => [ { label => 'SKU', width => 120 } ],
        rows     => [
            { value => 'AB-12', columns => ['AB-12'] },
            { value => 'AB-21', columns => ['AB-21'] },
            { value => 'CD-34', columns => ['CD-34'] },
        ],
        on_select => sub ($v) { { type => 'SET_PICKS', value => $v } }    # $v is an arrayref
    );

=head1 DESCRIPTION

L<Uji::Node::ListView> is a visible, scrollable multi-column list (a table). A single selection is stored as a scalar
in the model; with L</multiple> the value is an B<arrayref> of selected row values. On Win32 it is a native
C<SysListView32> in report (details) view.

=head1 Constructor

=head2 C<new ( %params )>

You normally use the L<Uji|Uji/list_view> helper.

=head3 Parameters

=head4 C<value>

The currently selected row's C<value>. With L</multiple> it is an arrayref of selected row values. Default C<''>.
Recomposed live by the reconciler.

=head4 C<columns>

Array reference of C<< { label => ..., width => ... } >> hashrefs defining the column headers. C<width> (pixels)
defaults to the measured label width, C<label> defaults to C<''>. When the columns change the reconciler rebuilds the
table.

=head4 C<rows>

Array reference of the rows. Each row is either an arrayref of cell strings or a C<< { value => ..., columns => [...] } >>
hashref; in the arrayref form the row's C<value> defaults to the first cell. When the rows change the reconciler
rebuilds the table's contents.

=head4 C<on_select>

A callback receiving the selected row's C<value> (or an arrayref of them when L</multiple>):

    on_select => sub ($v) { { type => 'SET_SKU', value => $v } }

Return a message hashref (or C<undef> to ignore the event).

=head4 C<multiple>

Boolean, default false. When true the table allows several rows to be selected at once and the value (and C<on_select>
argument) is an arrayref of the selected row values. The Win32 control drops the C<LVS_SINGLESEL> style so ordinary
clicks toggle each row.

=head4 C<full_row_select>

Boolean, default false. When true the entire row highlights on selection (the C<LVS_EX_FULLROWSELECT> extended style).

=head4 C<grid_lines>

Boolean, default false. When true the table draws cell separator lines (the C<LVS_EX_GRIDLINES> extended style).

=head4 C<header>

Boolean, default true. When false the column header bar is hidden (the C<LVS_NOCOLUMNHEADER> style).

=head3 Inherited Parameters

L<Uji::Node::ListView> inherits the common parameters from L<Uji::Node|Uji::Node/Parameters>: C<flex>, C<enabled>,
C<visible>, C<tooltip>, C<x>/C<y>/C<w>/C<h>, and C<id>.

=head1 Methods

=head2 C<value>

Returns the selected row's C<value> (or the arrayref of selected values when L</multiple>).

=head2 C<columns>

Returns the array reference of C<< { label => ..., width => ... } >> columns.

=head2 C<rows>

Returns the array reference of rows.

=head2 C<on_select>

Returns the selection callback (or C<undef>).

=head2 C<multiple>

Returns true when the table allows multiple selections.

=head2 C<full_row_select>

Returns true when the whole row highlights on selection.

=head2 C<grid_lines>

Returns true when cell separator lines are drawn.

=head2 C<header>

Returns 1 when the column header bar is shown, 0 when it is hidden.

=head2 C<type>

Returns the string C<'list_view'>.

=head1 How it Works

On Win32 the table is a native C<SysListView32> created with the report view style C<LVS_REPORT> (C<0x1>) and
C<LVS_SHOWSELALWAYS> (C<0x8>); L</multiple> omits C<LVS_SINGLESEL> (C<0x4>) and L</header> adds C<LVS_NOCOLUMNHEADER>
(C<0x4000>). After creation the driver sets the extended styles C<LVS_EX_DOUBLEBUFFER> (C<0x10000>) and, per
L</full_row_select> and L</grid_lines>, C<LVS_EX_FULLROWSELECT> (C<0x20>) and C<LVS_EX_GRIDLINES> (C<0x1>) via
C<LVM_SETEXTENDEDLISTVIEWSTYLE>.

Columns are added with C<LVM_INSERTCOLUMNW> and an 72-byte C<LVCOLUMNW> packed to the Win64 layout (mask/fmt/cx at
0/4/8, pszText at 16). The first column of each row is inserted with C<LVM_INSERTITEMW>; later cells are written into
the existing item with C<LVM_SETITEMW> (C<LVM_SETITEMTEXTW> is avoided: it silently no-ops for subitems). All text is
UTF-16, copied by the control during the call so the buffers are freed immediately.

The model's selection is applied with C<LVM_SETITEMSTATE> carrying an C<LVITEMW> (mask C<LVIF_STATE>, state and
stateMask C<LVIS_SELECTED>); all rows are cleared first, then each matching row is selected and scrolled into view with
C<LVM_ENSUREVISIBLE>. User clicks raise C<LVN_ITEMCHANGED>, whose row index is routed back to the model value through a
driver-side slot table (and, for L</multiple> tables, the whole native selection is read back via C<LVM_GETITEMCOUNT> /
C<LVM_GETITEMSTATE>). Programmatic selection is suppressed so the native echo never dispatches a spurious C<on_select>.

The I<len> used by L<Uji::Layout|Uji::Layout/DESCRIPTION> is the value stored in the model, never a handle-mutating
call.
