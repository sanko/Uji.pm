=head1 NAME

Uji::Node::SpinBox - a number entered or stepped with an up/down spinner

=head1 SYNOPSIS

    use Uji;

    Uji::spin_box(
        value     => $model->{copies},
        min       => 1,
        max       => 99,
        step      => 1,
        on_change => sub ($n) { { type => 'SET_COPIES', value => $n } }
    );

=head1 DESCRIPTION

L<Uji::Node::SpinBox> is a numeric editor: a read-only text field plus an up/down spinner. The user either types a
value or clicks the arrows; either way the position is a plain number between C<min> and C<max>, exclusive of nothing
and stepped by C<step>. Unlike L<Uji::Node::Slider|Uji::Node::Slider> it shows the exact number.

Because the edit field is read-only (the driver owns its text), the model scalar stays authoritative: re-rendering with
the same C<value> cannot drift, and the C<on_change> argument is always the number the control settled on.

=head1 Constructor

=head2 C<new ( %params )>

You normally use the L<Uji|Uji/spin_box> helper.

=head3 Parameters

=head4 C<value>

The current number. Default C<0>. Recomposed live.

=head4 C<min> / C<max>

The accepted range. Defaults C<0> and C<100>. Recomposed live.

=head4 C<step>

Arrow-click increment. Default C<1>. Recomposed live.

=head4 C<on_change>

A callback receiving the new number whenever the user changes it:

    on_change => sub ($n) { { type => 'SET_COPIES', value => $n } }

Return a message hashref (or C<undef> to ignore the event).

=head3 Inherited Parameters

L<Uji::Node::SpinBox> inherits the common parameters from L<Uji::Node|Uji::Node/Parameters>: C<flex>, C<enabled>,
C<visible>, C<tooltip>, C<x>/C<y>/C<w>/C<h>, C<color>, C<background>, C<font>, C<font_size>, and C<id>.

=head1 Methods

=head2 C<value>

Returns the current number.

=head2 C<min>, C<max>

Return the range bounds.

=head2 C<step>

Returns the arrow-click increment.

=head2 C<on_change>

Returns the change callback (or C<undef>).

=head2 C<type>

Returns the string C<'spin_box'>.

=head1 How it Works

On Win32 a spin box is two sibling controls placed SIDE BY SIDE: a read-only C<EDIT> (C<ES_READONLY | ES_AUTOHSCROLL>)
and a C<msctls_updown32> buddy. Mount applies the range with C<UDM_SETRANGE32> and the starting position with
C<UDM_SETPOS32>; live changes go the same way, and C<step> rides C<UDM_SETACCEL>. The driver is the editor of the
field text: it syncs the C<EDIT> from the spin value on mount, on C<set_prop('value')>, and after every C<WM_VSCROLL>
arrow press (keeping typed changes in step with the arrows). User input surfaces via the buddy's notifications, the
fresh value is read back with C<UDM_GETPOS32>, and the C<on_change> callback is handed that number.
