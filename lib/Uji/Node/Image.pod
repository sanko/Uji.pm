=head1 NAME

Uji::Node::Image - a static raster widget

=head1 SYNOPSIS

    Uji::image(
        src        => '/path/to/photo.png',           # or data:image/png;base64,...
        alt        => 'A photo',
        w          => 320,                             # omit: natural size
        h          => 200,
        object_fit => 'contain',                       # contain | cover | fill
    );

=head1 DESCRIPTION

An C<image> displays a static raster (PNG, JPEG, GIF, ICO, BMP - whatever GDI+ decodes) from a
file path or a C<data:image/...;base64,..> URI. It is a leaf widget whose natural box is the
raster's own size; an explicit C<w> or C<h> scales it while preserving the aspect ratio, and
setting both sizes the box freely.

The driver rasterizes the source into the widget's box on a STATIC C<SS_BITMAP> host, so what you
see is always scaled (not merely stretched by the control). C<object_fit> controls how the picture
maps onto that box:

=over

=item C<contain> (default)

The whole image fits inside the box, centred; the box keeps any leftover "letterbox" space.

=item C<cover>

The box is filled completely, cropping the excess from two opposite edges (a centre crop).

=item C<fill>

The image is stretched to the box exactly, ignoring the aspect ratio.

=back

Swap the picture live by re-rendering with a different C<src> or C<object_fit>: both map to the
driver's C<set_prop> path and re-raster in place, keeping the same control.

=head2 Parameters

=over

=item C<src>

A file path or a C<data:image/I<type>;base64,..> URI. Recomposed live.

=item C<alt>

An accessible description; the Win32 driver currently ignores it.

=item C<object_fit>

One of C<contain> (default), C<cover> or C<fill>. Recomposed live.

=item C<w>, C<h>

Explicit box; when one is zero the other follows the aspect ratio (see L<Uji::Node/Common Parameters>).

=back
