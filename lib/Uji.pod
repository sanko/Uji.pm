=head1 NAME

Uji - Modern, asynchronous GUI toolkit Built with FFI and Elm Architecture

=head1 SYNOPSIS

    use v5.40;
    use Uji;

    # The model is your UI's state and is the only mutable thing in the program. Every widget on
    # screen reads from it and nothing else tells the UI what to show.
    my $model = { count => 0 }; # Here, it's represented by a hash reference

    # init() produces the starting model and any initial commands. It runs exactly once, before the
    # window exists and returns ($model, $cmd); the $cmd half is reserved for background
    # side-effects and stays undef.
    sub init () {
        return ( $model, undef );
    }

    # update( ... ) folds a message into a new model. This is a pure function that's given the
    # ($msg, $model) and always returns the same model. User activity arrives here as plain hashref
    # messages (see on_click, on_input, on_toggle below).
    sub update ( $msg, $model ) {
        if ( $msg->{type} eq 'INCREMENT' ) {
            $model->{count} += 1;
        }
        elsif ( $msg->{type} eq 'RESET' ) {
            $model->{count} = 0;
        }
        return ( $model, undef );
    }

    # view() turns the model into a declarative widget tree. Called at startup and after every
    # batch of messages. Uji diffs each new tree against the previous one and applies only the
    # native updates that actually changed - so this isn't a full rebuild every time.
    sub view ($model) {
        Uji::window( # window() is the root of every view
            title    => 'Counter',
            w        => 320,          # outer width/height
            h        => 140,
            centered => 1,
            child    => Uji::column(  # stacks children top-to-bottom
                padding  => 15,       # space from the edge to the children
                spacing  => 12,       # gap between consecutive children
                children => [
                    Uji::text( 'Count: ' . $model->{count} ),   # a static label
                    Uji::row(         # lays children out left-to-right
                        spacing  => 10,
                        children => [
                            # flex => 2 is twice as wide as flex => 1.
                            # on_click is a static message, sent verbatim;
                            # the toolkit never touches this button again.
                            Uji::button( label => '+1',    flex => 2, on_click => { type => 'INCREMENT' } ),
                            Uji::button( label => 'Reset', flex => 1, on_click => { type => 'RESET' } )
                        ]
                    )
                ]
            )
        );
    }

    # run() mounts the window and starts the event loop after connecting the three callbacks. This
    # doesn't return until the window closes.
    Uji::app( init => \&init, update => \&update, view => \&view )->run;

=head1 DESCRIPTION

Uji is a concurrency-friendly GUI toolkit built with concepts from L<The Elm
Architecture|https://guide.elm-lang.org/architecture/> (TEA). The declarative API wraps native widgets via FFI. Your UI
is a pure function of your data.

Every Uji program is the same three functions:

    init()                -- the starting model
    view(model)           -- turns the model into a widget tree
    update(msg, model)    -- turns a message into a new model

The C<view> function renders the model as a declarative tree of native widgets; user gestures arrive as messages; and
the pure C<update> function folds each message into a new model. Uji owns everything else: windows, layout, event
plumbing, and the diffing that turns each render into minimal native updates. The UI can never drift out of sync with
the state that produced it, and all of it can be exercised headless.

=head2 Design Goals

=over

=item * B<Describe, don't manipulate>

You build the whole screen with the B<view> function; Uji figures out the smallest native update. No raw handles, no
imperative poking at widgets.

=item * B<The model is the source of truth>

Every visible property - a checkmark, a slider thumb, an edit box's text - derives from the model in B<view> and
changes only when the model changes.

=item * B<Asynchronous, cooperative>

Events and rendering run as L<Acme::Parataxis> fibers over a single message channel: responsive without threads, locks,
or callbacks.

=item * B<One layout, every platform>

Widget bounds are computed in pure Perl, so behavior is identical across backends and the layout is testable with no
window at all.

=back

=head2 An Introduction to The Elm Architecture

To really grasp how Uji works, you should be familiar with the Elm Architecture.

Here's a quick rundown...

=head3 The Trio

An Uji application is three callbacks passed to L</app>:

=over

=item C<init( )>

Returns C<< ( $initial_model, $initial_cmd ) >>. Runs once at startup. The C<$cmd> half is reserved for background
side-effects and is currently unused; return C<undef>. Time and platform events reach C<update> through
L</Subscriptions> instead.

=item C<update( $msg, $model )>

Returns C<< ( $new_model, $cmd ) >>. Pure (ideally): given the same message and model it produces the same model every
time. Mutating the model in place and returning it is acceptable, but see L</"Write Your update() As a Pure Function">.

=item C<view( $model )>

Returns a virtual window (see the helper functions in the next section). This is called once at mount time and again
after every batch of messages, and its output is diffed against the previous render.

=back

=head3 Messages

A message is a plain hash reference with a C<type> key:

    { type => 'INCREMENT' }
    { type => 'SET_NAME',  value => 'Sanko' }
    { type => 'SET_LEVEL', value => 62 }

The B<view> function attaches messages to widgets using the C<on_*> callback parameters. Two shapes are supported:

=over

=item * A static message hashref

    Uji::button( label => '+1', on_click => { type => 'INCREMENT' } );

Sent verbatim whenever the widget fires. Best for controls whose message carries no state.

=item * A callback returning a message hashref

    Uji::checkbox(
        label     => 'Dark mode',
        checked   => $model->{dark},
        on_toggle => sub ($on) { { type => 'TOGGLE_DARK', value => $on } }
    );

The callback receives the widget's current value as an argument and is expected to return a message (or C<undef> to
ignore the event). The arguments differ per widget:

    text_input / multiline_text / password
                on_input  -> sub ($text)  { ... }   # full text string
    slider      on_change -> sub ($value) { ... }   # numeric position
    spin_box    on_change -> sub ($value) { ... }   # numeric position
    date_picker on_change -> sub ($iso)   { ... }   # ISO-8601 'YYYY-MM-DD' ('' when cleared)
    checkbox    on_toggle -> sub ($on)    { ... }   # 1 or 0
    toggle_switch / toggle_button
                on_toggle -> sub ($on)    { ... }   # 1 or 0
    radio_group on_select -> sub ($value) { ... }   # selected option's value
    combo_box / list_box
                on_select -> sub ($value) { ... }   # selected option's value
    list_view   on_select -> sub ($value) { ... }   # selected row's value (arrayref with C<multiple>)
                on_sort   -> sub ($col, $dir) { ... }   # header click (with C<sortable>)
                on_reorder-> sub ($order) { ... }       # header drag (with C<reorderable>)
    tree_view   on_select -> sub ($value) { ... }   # selected item's value
    tab_panel   on_select -> sub ($index) { ... }   # selected panel index

=back

=head3 Subscriptions

User gestures are not the only source of messages. A model can also ask for messages from the outside world - a timer
firing, the window being resized - with a B<subscription>. You declare what the current model wants in the
C<subscriptions> callback passed to L</app>, and the runtime delivers those messages through the very same C<update>
path:

    Uji::app(
        init          => \&init,
        update        => \&update,
        view          => \&view,
        subscriptions => sub ($model) {
            return [
                Uji::sub_interval( 1000, { type => 'TICK' } ),
                Uji::sub_on_resize( { type => 'WINDOW_RESIZED' } ),
            ];
        }
    )->run;

Subscriptions are reconciled after every render: new ones start, ones the model no longer asks for stop, and a
surviving timer keeps its phase. See L<Uji::Sub> for the details.

=head2 The Render Pipeline

When the app starts, C<Uji::app(...)->run> does:

=over

=item 1. C<init> produces the initial model.

=item 2. C<view> renders it to a virtual tree.

=item 3. The driver creates the native window and controls I<at their measured, absolute positions>
(mount), and the tooltip infrastructure is wired up.

=item 4. An event pump fiber polls the message queue while a render fiber waits on the channel.

=item 5. Each user gesture B<is> a message. Messages are drained in batches, folded through
C<update>, and then C<view> is called once, producing a new virtual tree.

=item 6. A reconciler diffs the new tree against the old one and issues the smallest set of native
updates (positions, text, check state, ...).

=item 7. The subscription set is reconciled against the new model: timers start or stop, and resize
listeners deliver their messages on the next event.

=back

The key property: no matter how many messages arrive in a tick, the view is only re-rendered once per batch.

=head2 Write Your update() As a Pure Function

Elm's single most important convention is that the model is the L<source of
truth|https://en.wikipedia.org/wiki/Single_source_of_truth>, not the widgets. Advice that keeps things sane:

=over

=item Do B<not> read widget values inside C<update>.

The message already carries the value it needs (handed to your C<on_*> callback by the driver, which reads native state
at event time).

=item Do B<not> grab the native handle from the driver and mutate the widget.

There is a reconciler for that. If a property is missing from the model, add the property via the widget prop system
(see L</Lifecycle of a Property>) which is the only sanctioned mutation path.

=back

=head1 FUNCTIONS

All functions are exported by default. Each is a thin constructor for a L<Uji::Node|Uji::Node> subclass or the
application object.

=head2 C<app ( %args )>

Constructs the application runtime. Returns a L<Uji::App> object; call C<run> on it.

    Uji::app(
        init   => \&init,      # required
        update => \&update,    # required
        view   => \&view      # required
    )->run;

Optional parameters (rarely needed):

    driver        # a Uji::Driver instance (default: Uji::Driver::detect)
    channel       # a message channel
    reconciler    # a Uji::Reconciler
    layout        # a Uji::Layout
    subscriptions # sub ($model) { ... } - see L</Subscriptions>

=head2 C<sub_interval ( $ms, $msg, %opts )>

Requests C<$msg> every C<$ms> milliseconds as long as the C<subscriptions> callback returns it. C<$msg> can be a
message hashref or a coderef called with the current time in milliseconds. The timer keeps its phase across renders and
stops as soon as the subscription is dropped:

    Uji::sub_interval( 1000, { type => 'TICK' } );

See L<Uji::Sub/sub_interval>.

=head2 C<sub_on_resize ( $msg, %opts )>

Requests C<$msg> whenever the window is resized, as long as the C<subscriptions> callback returns it:

    Uji::sub_on_resize( { type => 'WINDOW_RESIZED' } );

See L<Uji::Sub/sub_on_resize>.

=head2 C<window ( %args )>

The root of every view. There is exactly one per view.

    Uji::window(
        title     => 'My App',
        w         => 380,          # outer size
        h         => 600,
        child     => Uji::column(...),
        centered  => 1,
        resizable => 1             # default
    );

Common parameters:

=over

=item C<title>

The window title. Default C<'Uji Application'>. Live-updates to the title bar.

=item C<w>, C<h>

Requested outer width/height. Default 0 (the platform decides).

=item child

The root layout container. Optional; a window with no child renders an empty content area.

=item centered

C<1> to center the window on screen at creation. Default 0.

=item C<resizable>

C<1> to allow user resizing, C<0> to fix the size. Default 1.

=item C<topmost>

C<1> to keep the window above all others. Default 0.

=item C<minimized> / C<maximized>

Initial window state flags. Default 0 each.

=item C<min_w> / C<min_h> / C<max_w> / C<max_h>

Track-size constraints enforced by the OS. 0 means unconstrained.

=back

=head2 C<column ( %args )>, C<row ( %args )>

Vertical / horizontal flex containers.

    Uji::column( padding => 15, spacing => 12, children => [ ... ] );

=over

=item C<children>

An array reference of child nodes. The container lays them out along its main axis, splitting remaining space among
children with C<flex E<gt> 0>.

=item C<padding>

Space between the container's edge and its children. Column default 10, row default 0.

=item C<spacing>

Gap between consecutive children. Column default 10, row default 10.

=back

=head2 C<text ( $label, %args )>

A static label. The first argument is positional.

    Uji::text( 'Hello, ' . $model->{name} );

The label is a plain string; the toolkit does no markup interpretation.

=head2 C<button ( %args )>

A push button that fires L</on_click>.

    Uji::button( label => '+1', on_click => { type => 'INCREMENT' } );

=over

=item C<label>

The button text. Default C<''>.

=item C<on_click>

A static message hashref, sent verbatim when the button is clicked or a callback C<sub { ... }> whose return value (a
message hashref, or C<undef>) is sent instead. See L</Messages> and L<Uji::Node::Button/on_click>.

=back

=head2 C<text_input ( %args )>

A single-line text editor.

    Uji::text_input(
        value    => $model->{name},
        readonly => $model->{locked},
        focused  => 1,
        on_input => sub ($text) { { type => 'SET_NAME', value => $text } }
    );

=over

=item C<value>

The editor's text. Default C<''>.

=item C<multiline>

C<0> (default) single-line; C<1> makes the same widget a scrolling multi-line text area. Recomposed live (recreative:
see L<Uji::Reconciler/Recreation>).

=item C<placeholder>

A faint grey hint shown while the editor is empty. Default C<undef> (no hint).

=item C<on_input>

Callback receiving the full text (C<sub ($text) { ... }>) whenever the user edits the control. Returns a message (or
C<undef>).

=item C<readonly>

C<1> to prevent editing. Default 0.

=item C<maxlength>

Maximum number of characters. 0 = unlimited.

=item C<focused>

C<1> to give the control keyboard focus at mount/on change. Default 0.

=back

=head2 C<multiline_text ( %args )>

A multi-line text editor that keeps the same parameters as L</text_input>:

    Uji::multiline_text(
        value    => $model->{body},
        readonly => $model->{locked},
        color    => '#0F7B0F',
        on_input => sub ($text) { { type => 'SET_BODY', value => $text } }
    );

Resolves to L<Uji::Node::MultilineText|Uji::Node::MultilineText>, a subclass whose C<multiline> is always on and never
changes; otherwise identical to L</text_input>. All of L</text_input>'s parameters apply.

=head2 C<password ( %args )>

A masked text editor (an edit control with E<sol>E<gt>C<ES_PASSWORD>). The native display is hidden; the message
payload is the plain text.

    Uji::password(
        value         => $model->{secret},
        password_char => '*',
        on_input      => sub ($t) { { type => 'SET_SECRET', value => $t } }
    );

Same parameters as L</text_input>, plus C<password_char> (the character drawn in place of each typed character;
C<undef> lets Windows pick its standard bullet).

=head2 C<slider ( %args )>

A horizontal or vertical range slider.

    Uji::slider(
        value       => $model->{level},
        min         => 0,
        max         => 100,
        step        => 1,               # or 25 when "locked"
        orientation => 'vertical',      # 'horizontal' (the default)
        on_change   => sub ($v) { { type => 'SET_LEVEL', value => $v } }
    );

=over

=item C<value>

Current position. Default 0.

=item C<min> / C<max>

Range endpoints. Defaults 0 / 100.

=item C<step>

Increment used by arrow-key / page interaction. Default 1.

=item C<orientation>

C<'horizontal'> (default) or C<'vertical'>. Recomposed live (recreative: see L<Uji::Reconciler/Recreation>).

=item C<on_change>

Callback receiving the numeric position. Returns a message (or C<undef>).

=back

=head2 C<spin_box ( %args )>

A numeric stepper: an edit box with up/down arrow buttons glued to its right edge. The value is read-only in the UI,
the arrows (or keyboard arrows, when focused) change it.

    Uji::spin_box(
        value     => $model->{count},
        min       => 0,
        max       => 100,
        step      => 5,
        on_change => sub ($v) { { type => 'SET_COUNT', value => $v } }
    );

=over

=item C<value>

Current number. Default 0.

=item C<min> / C<max>

Allowed range. Defaults 0 / 100.

=item C<step>

Increment applied to a single arrow click. Default 1.

=item C<on_change>

Callback receiving the new numeric position. Returns a message (or C<undef>).

=back

=head2 C<date_picker ( %args )>

A calendar/date entry control presenting an ISO-8601 C<YYYY-MM-DD> value. Purely a date picker in this
release (Win32 builds it from C<SysDateTimePick32>).

    Uji::date_picker(
        value     => $model->{date},
        format    => 'short',          # 'short' | 'long' | 'time'
        min       => '2020-01-01',
        max       => '2030-12-31',
        show_none => 1,                # a checkbox that clears the date
        on_change => sub ($iso) { { type => 'SET_DATE', value => $iso } }
    );

=over

=item C<value>

Current date as C<'YYYY-MM-DD'>, or C<undef> for no date at all. Recomposed live.

=item C<min> / C<max>

Natural (inclusive) date range as C<'YYYY-MM-DD'>; C<undef> for unbounded. Recomposed live.

=item C<format>

C<'short'> (default), C<'long'> or C<'time'>. Mount-time only; changing it live recreates the control.

=item C<show_none>

When true, the picker shows a checkbox the user can uncheck to mean "no date"; the change callback
then receives the empty string. Default false. Mount-time only.

=item C<useynavigate>

When true, the picker uses up/down arrows instead of the calendar dropdown. Default false. Mount-time only.

=item C<on_change>

Callback receiving the newly chosen date as C<'YYYY-MM-DD'> (C<''> when the date was cleared). Returns a
message (or C<undef>).

=back

=head2 C<progress_bar ( %args )>

A determinate progress (percentage-style) bar. Purely presentational; no callbacks.

    Uji::progress_bar( value => $model->{level}, min => 0, max => 100 );

=over

=item C<value>

Current fill position. Default 0.

=item C<min> / C<max>

Range endpoints. Defaults 0 / 100.

=back

=head2 C<spinner ( %args )>

An animated, indeterminate activity indicator (see L<Uji::Node::Spinner>): a rotating fan of
spokes sized to a C<size>-pixel square, drawn as an anti-aliased GDI+ icon fan with a dimming tail.
The driver pre-renders a dozen HICON frames and swaps them on an SS_ICON static host, clocked by a
dedicated WM_TIMER (id = the control id). Patch C<running> to start/stop.

    Uji::spinner( size => 28, color => '#0081C8', speed => 40, running => $model->{busy} );

=over

=item C<size>

Square size in pixels. Default 24 (clamped to >= 16).

=item C<color>

Spoke colour C<'#RRGGBB'>. Default C<'#2e5d8c'>.

=item C<speed>

Milliseconds per frame. Default 80. Recomposed live (re-arms the timer).

=item C<running>

C<1> to animate, C<0> to freeze. Default 1. Recomposed live.

=back

=head2 C<toggle_switch ( %args )> / C<toggle_button ( %args )>

Two-state controls with a sticky (pushed-in) look. Both behave like a checkbox, click to toggle, C<checked> state lives
in the model, but render as switches/buttons rather than a square box. The only difference is conceptual: a switch
reads as an on/off indicator, a toggle button as a stateful action.

    Uji::toggle_switch(
        label     => 'Enable editing',
        checked   => $model->{enabled},
        on_toggle => sub ($on) { { type => 'TOGGLE_ENABLED', value => $on } }
    );

    Uji::toggle_button(
        label     => ( $model->{locked} ? 'Locked' : 'Unlocked' ),
        checked   => $model->{locked},
        on_toggle => sub ($on) { { type => 'TOGGLE_LOCK', value => $on } }
    );

=over

=item C<label>

Text drawn on the control. Default C<''>.

=item C<checked>

C<1> for on/pushed, C<0> for off/released. Default 0.

=item C<on_toggle>

Callback receiving the post-click state (C<1> or C<0>). Returns a message (or C<undef>).

=back

=head2 C<link_button ( %args )>

A borderless "hyperlink-like" button. Its C<on_click> uses the same contract as C<button>: a static message hashref is
sent verbatim; a callback is invoked and its return value is sent.

    Uji::link_button( label => 'Visit docs', on_click => { type => 'OPEN_DOCS' } );

=over

=item C<label>

Text drawn on the button. Default C<''>.

=item C<on_click>

Message hashref, or a callback returning one (or C<undef>).

=back

=head2 C<checkbox ( %args )>

A toggle box. Fires L</on_toggle> on every click with the new state.

    Uji::checkbox(
        label     => 'Dark mode',
        checked   => $model->{dark},
        on_toggle => sub ($on) { { type => 'TOGGLE_DARK', value => $on } }
    );

=over

=item C<label>

Adjacent text. Default C<''>.

=item C<checked>

C<1> for checked, C<0> for unchecked. Default 0.

=item C<on_toggle>

Callback receiving C<1> or C<0>. Returns a message (or C<undef>).

=back

=head2 C<radio_group ( %args )>

An exclusive-choice group; the group is stored as a single scalar in the model.

    Uji::radio_group(
        value   => $model->{color},
        options => [
            { value => 'red',   label => 'Red' },
            { value => 'green', label => 'Green' },
            { value => 'blue',  label => 'Blue' }
        ],
        on_select => sub ($v) { { type => 'SET_COLOR', value => $v } }
    );

=over

=item C<value>

The currently selected option's C<value>. Default C<''>.

=item C<options>

Array reference of C<< { value => ..., label => ... } >> hashrefs. The C<label> defaults to the C<value>.

=item C<spacing>

Gap between the radio buttons. Default 4.

=item C<on_select>

Callback receiving the selected option's C<value>. Returns a message (or C<undef>).

=back

Radios are created internally as L<Uji::Node::Radio> children whose L<Uji::Node> ids are memoized per group instance,
so the native checkboxes keep stable handles across re-renders even as the model changes the selection.

=head2 C<combo_box ( %args )>

A dropdown selection; on Win32 a native combo box. Non-editable by default, selectable from the list.

    Uji::combo_box(
        value   => $model->{color},
        options => [
            { value => 'red',   label => 'Red' },
            { value => 'green', label => 'Green' },
            { value => 'blue',  label => 'Blue' }
        ],
        on_select => sub ($v) { { type => 'SET_COLOR', value => $v } }
    );

=over

=item C<value>

The currently selected option's C<value>. Default C<''>.

=item C<options>

Array reference of C<< { value => ..., label => ... } >> hashrefs. The C<label> defaults to the C<value>.

=item C<editable>

When true, the box is an editable dropdown (C<CBS_DROPDOWN>): the user can type free text or pick a listed option.
Default 0.

=item C<on_select>

Callback receiving the selected option's C<value>; for an editable box that has been typed instead of picked, it
receives the typed text. Returns a message (or C<undef>).

=item C<on_input>

For editable boxes: callback receiving the current text on every edit (the C<CBN_EDITCHANGE> path). Returns a message
(or C<undef>).

=back

=head2 C<list_box ( %args )>

A visible, scrollable list; a single selection by default, or multiple selections with C<multiple>.

    Uji::list_box(
        value     => $model->{count},
        options   => [ map { { value => $_, label => "Row $_" } } 1 .. 10 ],
        on_select => sub ($v) { { type => 'SET_COUNT', value => $v } }
    );

    # Multi-select: ordinary clicks toggle each row; value is an arrayref.
    Uji::list_box(
        multiple  => 1,
        value     => [ 2, 5 ],
        options   => [ map { { value => $_, label => "Row $_" } } 1 .. 10 ],
        on_select => sub ($v) { { type => 'SET_PICKS', value => $v } }
    );

=over

=item C<value>

The currently selected option's C<value>. With C<multiple> it is an arrayref of selected option values. Default C<''>.

=item C<options>

Array reference of C<< { value => ..., label => ... } >> hashrefs. The C<label> defaults to the C<value>.

=item C<multiple>

Boolean, default false. When true the list allows several rows to be selected at once; the value (C<value>) and the
C<on_select> argument become arrayrefs of the selected option values.

=item C<on_select>

Callback receiving the selected option's C<value> (or an arrayref of them for C<multiple> lists). Returns a message (or
C<undef>).

=back

=head2 C<list_view ( %args )>

A multi-column, scrollable selection list (a table); a single selection by default, or multiple selections with
C<multiple>.

    Uji::list_view(
        value   => $model->{sku},
        columns => [
            { label => 'SKU',   width => 120 },
            { label => 'Name',  width => 200 },
            { label => 'Price', width => 80 },
        ],
        rows => [
            ['AB-12', 'Apples',  '3'],
            { value => 'CD-34', columns => ['CD-34', 'Cherries', '5'] },   # value defaults to the first cell
        ],
        on_select => sub ($v) { { type => 'SET_SKU', value => $v } }
    );

    # Multi-select: ordinary clicks toggle each row; value is an arrayref.
    Uji::list_view(
        multiple => 1,
        value    => ['AB-12', 'CD-34'],
        columns  => [ { label => 'SKU', width => 120 } ],
        rows     => [
            { value => 'AB-12', columns => ['AB-12'] },
            { value => 'CD-34', columns => ['CD-34'] },
        ],
        on_select => sub ($v) { { type => 'SET_PICKS', value => $v } }
    );

=over

=item C<value>

The selected row's C<value>. With C<multiple> it is an arrayref of selected row values. Default C<''>.

=item C<columns>

Array reference of C<< { label => ..., width => ... } >> hashrefs. C<width> defaults to the measured label width. The
optional per-column keys: C<sort> (C<'text'> or C<'numeric'>, default C<'text'>) chooses the comparator used when the
column is clicked (so numeric columns sort numerically even when C<formatted>), C<format> (an C<sprintf> format such as
C<'$%0.2f'>) formats numeric cells for display (cells always C<sort> by their raw value), and C<align> (C<'left'>,
C<'center'> or C<'right'>, default C<'left'>) picks the header-and-cell alignment. Clicking the sorted column's header
also stamps a sort-direction glyph (C<▲> ascending / C<▼> descending) into that label, which follows the column when
headers are drag-reordered.

=item C<rows>

Array reference of rows, each an arrayref of cell strings or a C<< { value => ..., columns => [...] } >> hashref (the
C<value> defaults to the first cell).

=item C<multiple>

Boolean, default false. When true the table allows several rows to be selected at once; the value and the C<on_select>
argument become arrayrefs of the selected row values.

=item C<full_row_select>

Boolean, default false. When true the whole row highlights on selection.

=item C<grid_lines>

Boolean, default false. When true the table draws cell separator lines.

=item C<header>

Boolean, default true. When false the column header bar is hidden.

=item C<on_select>

Callback receiving the selected row's C<value> (or an arrayref of them for C<multiple> tables). Returns a message (or
C<undef>).

=item C<sortable>

Boolean, default false. When true clicking a column header reorders the visible rows by that column (each column's
C<sort> key picks the comparator) and raises C<on_sort>.

=item C<on_sort>

Callback received after a header click: C<sub ($col, $dir)>, C<$col> the column index and C<$dir> C<'asc'>/C<'desc'>.
See L<Uji::Node::ListView/C<on_sort>>.

=item C<reorderable>

Boolean, default false. When true the user can drag column headers to reorder the columns; the new order is reported
through C<on_reorder>.

=item C<on_reorder>

Callback received after a column reorder: C<sub ($order)>, C<$order> the new left-to-right column indexes. See
L<Uji::Node::ListView/C<on_reorder>>.

=back

=item C<label>

=item C<align>

=head2 C<status_bar ( %args )>

=over

=item C<label>

The single-pane text. Default C<''>. Recomposed live.

=item C<panels>

=head2 C<group_box ( %args )>

An etched frame with a title band around a set of controls; a plain layout container with visual grouping only.

    Uji::group_box(

        spacing  => 8,

=over

=item C<label>

=item C<children>

=item C<padding>

=item C<spacing>

=head2 C<scroll_view ( $child, %opts )>

A viewport that clips one content subtree and shows native scrollbars when it overflows. The first argument is positional.

    Uji::scroll_view(
        Uji::column( spacing => 6, padding => 6,
            children => [ map { Uji::text("Line $_") } 1 .. 30 ] ),
        orientation => 'vertical',
        on_scroll   => sub ($x, $y) { { type => 'SCROLLED', x => $x, y => $y } }
    );

=over

=item C<orientation>

C<'vertical'> (default), C<'horizontal'>, or C<'both'>. Fixed at mount time (requires C<recreate_node>).

=item C<scroll_x> / C<scroll_y>

The initial scroll offsets in px (default C<0>). Recomposed live; out-of-range offsets are clamped.

=item C<on_scroll>

A callback receiving C<($x, $y)>, the current offsets. Return a message (or C<undef>).

=back

Content is laid out at its natural size and moved inside the clipped window, so it never wraps or shrinks; with no
main size the viewport FILLs its container.

=head2 C<split_view ( $a, $b, %opts )>

A resizable two-pane split. The two panes are positional.

    Uji::split_view(
        Uji::column( children => [ Uji::text('File'), Uji::button( label => 'Open', ... ) ] ),
        Uji::scroll_view( Uji::multiline_text( value => $model->{body}, ... ) ),
        orientation => 'horizontal',
        divider     => 260,
        on_divider  => sub ($pos) { { type => 'SET_DIVIDER', value => $pos } }
    );

=over

=item C<orientation>

C<'vertical'> (default) stacks the panes top-to-bottom; C<'horizontal'> places them side by side. Fixed at mount time.

=item C<divider>

Pane A's extent in px along the main axis. C<undef> (default) centers the split. Recomposed live; clamped to the pane
minima.

=item C<divider_w>

The drag-handle thickness in px. Default C<6>.

=item C<min_a> / C<min_b>

The minimum main-axis extent (px) of each pane. Defaults C<40>.

=item C<on_divider>

A callback receiving the clamped divider position after a drag. Return a message (or C<undef>).

=back

A tabbed set of switchable sub-views.

=over

=item C<panels>

=item C<index>

=item C<on_select>

=head2 C<tree_view ( %args )>

A hierarchical selection tree stored as nested hashrefs in the model.

    Uji::tree_view(

            { value => 'a', label => 'Alpha', children => [

=over

=item C<value>

=item C<nodes>

=item C<expanded>

A horizontal row of actions (text, optional per-button C<icon>) with optional separators.

        icon_size => 16,
        buttons => [
            { label => 'New', id => 'new', checked => 1,
              icon  => 'data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAgAAAAICAYAAADED76LAAAAFklEQVR4nGP8z8Dwn4EIwERQxQwwAAAoWgHJi0x4WQAAAABJRU5ErkJggg==' },

=head2 C<menu_bar ( %args )>

A window frame menu bar; attach it to L</window> with C<< menu_bar => ... >> rather than placing it as a layout child.

    Uji::menu_bar(
        items => [
            { label => 'File', children => [
                { label => 'New',  id => 'new' },
                { label => 'Exit', id => 'exit' },
            ]},
            { label => 'Edit', children => [
                { label => 'Undo', id => 'undo' },
                { separator => 1 },
                { label => 'Search', id => 'search' },
            ]},

A callback receiving the chosen leaf item's C<id>. Return a message (or C<undef>).

=head2 C<separator ( %args )>

A thin ruled divider line between siblings. In a column it draws a horizontal rule spanning the column width; in a row, a

    Uji::column( children => [
        Uji::text('Above'),
        Uji::separator(),                 # horizontal rule across the column
        Uji::text('Below'),
    ] );

=item C<orientation>

C<'horizontal'> (default, for columns) or C<'vertical'> (for rows). A mount-only parameter.

=head2 C<search_input ( %args )>

A single-line search field (see L<Uji::Node::SearchInput>): a plain C<EDIT> with an optional leading
18px C<E<0x2715>>-clearing button. Typing fires C<on_input> with the live text; clicking the C<E<0x2715>>

    Uji::row( children => [
        Uji::search_input(
            placeholder => 'Search…',
            icon        => 'data:image/png;base64,iVBOR…',
            on_input    => sub ($t) { { type => 'QUERY', text => $t } },
        ),
        Uji::button( label => 'Search', on_click => { type => 'RUN_SEARCH' } ),
    ] );

=over

=item C<value>

The current query text (default C<''>). Programmatic changes show/hide the C<E<0x2715>> button.

=item C<placeholder>

Grey hint text shown while empty.

=item C<icon>

Optional C<data:image/...> URI for the 16px leading glyph. Mount-only.

=item C<on_input>

C<sub ($text)> fired on every keystroke; return a message hashref or C<undef>.

=item C<on_search>

C<sub ($text)> fired when C<E<0x2715>> clears the field. Enter-key submission is not yet wired.

=head2 C<calendar ( %args )>

A month grid (see L<Uji::Node::Calendar>) built from ordinary toolkit controls: a C<E<0x25C0>> month-title
C<E<0x25B6>> header, a weekday-letter row, and six rows of day cells. Picking a day fires C<on_select> with the
ISO date; C<E<0x25C0>>/C<E<0x25B6>> fire C<on_nav> with C<-1>/C<+1> so the app can step C<month>. Days outside
C<min>/C<max> are disabled, and the selected day is highlighted.

    Uji::column( children => [
        Uji::calendar(
            month     => '2026-05',
            value     => '2026-05-04',
            min       => '2026-05-01',
            max       => '2026-05-31',
            on_select => sub ($iso) { { type => 'PICKED', value => $iso } },
            on_nav    => sub ($d)    { { type => 'MONTH', delta => $d } },
        ),
    ] );

=over

=item C<month>

The displayed month as C<'YYYY-MM'> (default: C<value>'s month, else the current month).

=item C<value>

The selected day as ISO C<'YYYY-MM-DD'>; its cell is highlighted (C<#BBD8F4>).

=item C<min>, C<max>

ISO boundaries; day cells outside the range are disabled.

=item C<on_select>

C<sub ($iso)> fired when a day cell is clicked; return a message hashref or C<undef>.

=item C<on_nav>

C<sub ($delta)> fired by the C<E<0x25C0>>/C<E<0x25B6>> header buttons (C<-1>/C<+1>); step C<month> in your
view function and return a message.

=back

=head2 C<overlay ( %args )>

A container (see L<Uji::Node::Overlay>) that stacks every child in the SAME plane: array order is the
draw order, later layers painting over earlier ones - the toolkit's version of CSS absolute
positioning. Each layer sizes itself by the usual rules and is offset within the box by its
C<align_w>/C<align_h>, so a corner "badge" on top of a full-frame layer is a one-liner.

    Uji::overlay(
        children => [
            Uji::text( 'A demo frame', w => 388, h => 180, align => 'center' ),
            Uji::button( label => '5 hits', fit => 'content', align_w => 'end', align_h => 'end' ),
        ],
    );

=over

=item C<children>

The layers, in draw order (last on top). Recomposed live.

=item C<padding>

Inset around the shared layer box. Default C<0>. Recomposed live.

=back

=head2 C<image ( %args )>

A static raster widget (see L<Uji::Node::Image>): displays a picture - from a file path or a
C<data:image/...;base64,..> URI - sized to its natural raster dims, an explicit C<w>/C<h>, or a mix
of the two (the free axis follows the aspect ratio). The picture is rasterized into the widget's
box by the driver, with C<object_fit> controlling the mapping.

    Uji::image(
        src        => 'logo.png',          # or data:image/png;base64,...
        w          => 160,
        h          => 70,
        object_fit => 'contain',           # contain | cover | fill
    );

=over

=item C<src>

A file path or a C<data:image/I<type>;base64,..> URI. Recomposed live.

=item C<alt>

An accessible description (unused by the Win32 driver).

=item C<object_fit>

C<contain> (default): the whole image fits inside the box, centred. C<cover>: the box is filled,
excess cropped. C<fill>: stretched to the box, ignoring the aspect. Recomposed live.

=back

=head2 C<canvas ( %args )>

A raw 2D drawing surface (see L<Uji::Node::Canvas>): a frameless box whose content is a callback.
C<on_draw> receives a L<Uji::Draw> session already cleared to C<background> and sized to the laid-out
box; it redraws on every WM_PAINT and whenever C<redraw> is bumped by a render.

    Uji::canvas(
        w          => 320,
        h          => 220,
        background => '#F0F0F0',
        on_draw    => sub ($d) {
            $d->clear('#FFFFFF');
            $d->color('#CC0000');
            $d->rect( 2, 2, $d->size );
        },
    );

=over

=item C<on_draw>

A C<Coderef> receiving the one L<Uji::Draw> session. Recomposed live (a changed callback repaints).

=item C<redraw>

An unsigned bump counter; a changed value invalidates the surface so a repaint follows. The canvas has
no intrinsic content, so its natural box is (200, 100) unless an explicit C<w>/C<h> is given.

=back

=head1 COMMON NODE PARAMETERS

Every widget (and the window) accepts the following parameters, provided by the base class L<Uji::Node>:

=over

=item C<id>

A stable identifier, normally auto-generated (101, 102, ...). Handles are keyed by id for the lifetime of a widget; the
reconciler preserves ids across renders. Provide your own only when you need a stable external key.

=item C<x>, C<y>, C<w>, C<h>

Requested position/size, used by layout. The computed position lives in the C<bx>/C<by>/C<bw>/C<bh> readers after a
layout pass - prefer C<flex> over manual sizing in containers.

=item C<flex>

A proportionality hint (0 = natural size, 1 = take a share of free space). In a row with two C<flex> buttons, C<flex
=E<gt> 2> is twice as wide as C<flex =E<gt> 1>.

=item C<enabled>

C<1> to accept input, C<0> to grey it out. Default 1.

=item C<visible>

C<1> to show, C<0> to hide and release layout space. Default 1.

=item C<tooltip>

A short hover tooltip string. Default C<undef> (no tooltip).

=back

=head1 The Message Round-Trip, Annotated

Here is the full journey of a single button click:

=over

=item 1. The user presses the native button.

=item 2. The OS posts C<WM_COMMAND> to the window procedure.

=item 3. The driver looks up the control in its registry, reads any state the handler needs (e.g.
L<BM_GETCHECK>), and calls your C<on_click> / C<on_toggle> / C<on_select> / C<on_input> /
C<on_change> handler.

=item 4. The resulting message hashref is C<put> onto the channel.

=item 5. The render fiber wakes, drains every pending message, and folds them through C<update> in
order.

=item 6. C<view> rebuilds the entire virtual tree from the new model.

=item 7. The reconciler walks the old and new trees side-by-side, transfers ids, and emits native
updates (position moves, text/check/state changes) only where a property actually changed.

=item 8. The native controls reflect the new model.

=back

=head1 Lifecycle of a Property

To expose a widget property to the model, all three layers must agree on its name. The pattern for any property (the
toolkit's own widgets are built this way):

=over

=item 1. A C<field $prop : param : reader> on the node class.

=item 2. A C<can('prop')> diff in L<Uji::Reconciler|Uji::Reconciler>'s C<patch>, so a change
triggers L<set_prop>.

=item 3. A branch in the platform driver's C<set_prop> that applies the value to the native
control.

=back

This is why the toolkit can run the entire render cycle headless: point the reconciler at a mock driver and the
"native" side is just a hash of recorded calls (see C<t/lib/MockDriver.pm>).

=head1 Event Loop and Sub-processes

C<run> never returns while the window is open; the process exits when the window is destroyed. Internally two
L<Acme::Parataxis> fibers cooperate: one pumps platform events with non-blocking polls, the other blocks on the message
channel. The C<RESIZE> and C<QUIT> message types are reserved for internal use - do not send or filter them from your
C<update> function.
